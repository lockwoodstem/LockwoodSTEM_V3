Slide 3

OPENING PROMPT

How do designs improve?

  • Use this as a quick class discussion while attendance is taken.
  • Think first. What should an engineer do after a first prototype does not work perfectly?
  • Quick class share
  • Raise your hand and share one action that can improve a design.
  • Student answers might include: test, measure, compare, revise, ask users, or try again.
  • We will reveal how those actions fit into the design process on the next slide.
Reveal answer / debrief

OPENING DEBRIEF

  • Design Process Cycle
  • A working definition for the year.
  • The engineering design process is a flexible cycle for defining, building, testing, revising, and communicating solutions.
  • Define
  • Clarify the goal, criteria, and constraints.
  • Generate
  • Create more than one possible solution.
  • Test
  • Collect evidence from prototypes or models.
  • Revise
  • Improve the design based on evidence.
  • Today's mission: use a paper airplane challenge to make the design cycle visible.

Slide 7

DESIGN CYCLE

Engineering Design Process

  • The process is flexible, not a strict checklist.
  • Core stages
  • Define the problem
  • Generate concepts
  • Develop a solution
  • Construct and test
  • Evaluate results
  • Today's challenge
  • Sketch one idea
  • Build Version 1
  • Record test distance
  • Revise the design
  • Compare Version 2
Slide 8

CHALLENGE SETUP

Paper Airplane Distance Challenge

  • Use a fast cycle with measurable evidence.
  • Challenge rules
  • One sheet for Version 1
  • One official test flight
  • Record distance
  • One sheet for Version 2
  • Compare evidence
  • Then answer:
  • What would make the second airplane a true revision instead of a random rebuild?
  • Process habits
  • Sketch
  • Show the initial concept.
  • Build
  • Create Version 1.
  • Measure
  • Record flight distance.
  • Revise
  • Change one or more features.
  • Explain
  • Connect the change to evidence.
  • Share-out target: one design change + the evidence that would justify it.
Slide 9

PROCESS SHIFT

Trial-and-Error vs. Engineering Revision

  • The goal is not random changes; the goal is evidence-based improvement.
  • Trial-and-error
  • Unclear learning
  • Changes are random
  • Results may not be recorded
  • Cause is hard to explain
  • Progress is difficult to prove
  • Engineering revision
  • Evidence-based
  • Changes have a reason
  • Test results are recorded
  • Cause can be discussed
  • Improvement can be defended
Slide 10

KEY IDEA

Test → Evaluate → Revise

  • Testing only matters if the team uses the results to make a decision.
  • Test
  • Measure the actual performance
  • Evaluate
  • Compare results to the goal
  • Revise
  • Change the design with a reason
  • Evidence can include…
  • Distance
  • Direction
  • Stability
  • Fold changes
  • Observations
  • Comparison
Slide 11

MINI CHALLENGE

What Evidence Would Support a Revision?

  • Read the claim. Select the two strongest supports.
  • Claim:
  • “Version 2 improved because we changed the wing fold after testing Version 1.”
  • Vote for the two strongest supports.
  • A
  • Version 1 and Version 2 flight distances
  • B
  • A statement that Version 2 looks cooler
  • C
  • Notes describing the wing-fold change
  • D
  • A teammate saying it felt better
  • E
  • A photo with no labels
  • Vote first. Then we will reveal the best evidence pair.
Reveal answer / debrief

EVIDENCE REVEAL

  • What Evidence Would Support a Revision?
  • The best support connects performance data to the design change.
  • Best support: A + C
  • A
  • Version 1 and Version 2 flight distances
  • Shows whether performance changed.
  • C
  • Notes describing the wing-fold change
  • Shows what was revised and why it matters.
  • Useful, but not enough alone: photos and opinions help only when connected to measurements or observations.
Slide 13

SCENARIO RESPONSE

What Should the Team Do Next?

  • Choose the strongest next step and explain your reasoning.
  • Version 1 flies far but curves sharply left every time. The team wants to improve Version 2.
  • A
  • Make random changes until it looks different.
  • B
  • Keep the design because it traveled far once.
  • C
  • Record the curve, identify a likely cause, change the folds, and retest.
  • D
  • Ignore the direction because only distance matters.
  • Vote first. Then we will reveal the strongest next step.
Reveal answer / debrief

SCENARIO REVEAL

  • What Should the Team Do Next?
  • The best next step turns repeated behavior into useful evidence.
  • Best answer: C
  • Record the curve, identify a likely cause, change the folds, and retest.
  • Record
  • Write down repeated flight behavior.
  • Identify
  • Choose a likely cause to revise.
  • Retest
  • Compare Version 2 to Version 1.
  • Engineering move: use repeated observations to guide a specific design change.

  • Vote: process or guessing?
  • Vote first. Then we will reveal which statements are strongest.
Reveal answer / debrief

QUICK CHECK REVEAL

  • Process or Guessing?
  • Strong design-process statements connect change to evidence.
  • A
  • Guessing
