01 / Programming Concepts

Clean Python Is Easier to Test

5 min • Review 3.8 code10 min • Functions and constants20 min • Refactor and test5 min • Compare evidence5 min • PDF export

Reusable functions

Wrap repeated behaviors in named functions such as command_motor(), tank_step(), and arcade_step(). Each function should have one clear purpose.

Named constants

Use MAX_SPEED, DEADBAND, and a named loop interval instead of repeating unexplained numbers. Constants make tuning consistent.

Single control loop

Read the controller at a predictable interval; compute commands; stop when the input is neutral. Never run tank and arcade command loops simultaneously.

Behavior-preserving changes

Refactoring changes how a program is organized, not its intended behavior. Compare the previous and revised version on the same tests before qualifying the rover.

Refactoring pattern (illustrative)

This pattern assumes your VEXcode V5 Python project already defines the connected controller and drive motors. Keep the motor directions, port assignments, and approved safe stopping procedure from 3.8. It is an example of organization, not a drop-in replacement project.

# Pseudocode pattern for your configured VEXcode V5 Python project.
# Use your existing working VEX devices and names from Lesson 3.8.
DEADBAND = 10
MAX_SPEED = 50

def clamp(value, minimum, maximum):
    return max(minimum, min(maximum, value))

def read_axis(axis):
    raw = axis.position()
    return 0 if abs(raw) <= DEADBAND else raw

def command_motor(motor, percent):
    speed = clamp(percent, -MAX_SPEED, MAX_SPEED)
    if speed == 0:
        motor.stop()
    elif speed > 0:
        motor.spin(FORWARD, speed, PERCENT)
    else:
        motor.spin(REVERSE, -speed, PERCENT)

def arcade_step():
    forward = read_axis(controller_1.axis3)
    turn = read_axis(controller_1.axis1)
    command_motor(left_motor, forward + turn)
    command_motor(right_motor, forward - turn)

# Inside the existing VEXcode project:
while True:
    arcade_step()
    wait(20, MSEC)

# To preserve tank mode, write a separate tank_step() function.
# Use only one control mode in the active loop at a time.

Safety: Download the original code before editing, verify motor commands with wheels clear of the floor, and run slow controlled movement tests. Do not install the arm or claw yet. The final code must retain a reliable neutral-stick stop.
