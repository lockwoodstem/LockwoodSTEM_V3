ADM Project 2.1.7

Automated Sorting Challenge

Integrate sensing, conveyors, robotic movement, and routing into a repeatable sorting system that transfers multiple product types across connected workcells.

Unit 2 Progression

Sense → Decide → Move → Communicate → Monitor → Optimize → Integrate

Unit 2 applies the programming foundation from Unit 1 to increasingly connected manufacturing systems.

Objective

Work toward the lesson goal: Automated Sorting Challenge. Use the directions and success criteria in the activity below.

Materials

For the online work: a browser and your engineering notebook. Follow the activity’s materials list for any physical build, and get teacher approval before using equipment.

Plan your time

Suggested work block: 45–60 minutes. Physical builds and projects may span several classes; follow your teacher’s schedule.

Learning Targets

By the end of this lesson

  • Integrate multiple workcell subsystems into one automated process.
  • Route multiple object types to defined destinations.
  • Coordinate work between two student teams and two workcells.
  • Test, debug, and document system reliability.
Equipment & Systems

What you will use

  • Two VEX CTE Workcells
  • Disks and Cubes
  • Conveyors and Diverters
  • 6-Axis Arms
  • Optical / Object Sensors
Project 2.1.7 · PLTW Double Dock Challenge

November 5–10: Program, Test, and Demonstrate

Work with a partner team to program two VEX CTE Workcells to sort 21 objects from Workcell 1 to the correct destination A, B, C, or D. On November 5 and 6, use VEXcode EXP and your engineering notes only. Do not use, energize, change, or test the physical workcells while your instructor is away.

Thursday, Nov 5 · Day 1/4

  1. Read the project requirements and the shipping destinations below.
  2. Meet with the partner team; assign responsibility for each workcell's code.
  3. Create a routing flowchart for disks and cubes, including detection, transport, diversion, transfer, and pallet placement.
  4. Start one VEXcode EXP program for each workcell, using descriptive function names, sensor conditions, loops, and comments.

Save: both draft programs, destination plan, and team responsibilities.

Friday, Nov 6 · Day 2/4

  1. Finish both programs and the cross-workcell handoff sequence.
  2. Perform a logical dry-run for red disks, green disks, and blue cubes headed to each of A–D—without hardware.
  3. Identify at least three possible failure cases, such as wrong sensor input, a late transfer, or an object not being detected; explain the expected program response.
  4. Review code together, add comments, and list hardware commands or movements that require checking Monday.

Save: both commented programs, dry-run log, and Monday testing checklist.

Monday, Nov 9 · Day 3/4

  1. With your instructor present, inspect the connected workcells before operating.
  2. Test individual motions and routes before a full run.
  3. Adjust sensor logic, coordinates, timing, handoffs, and actuator commands as needed.
  4. Record each failure, the code change made, and the retest result.

Save: tested program files and troubleshooting log. Prepare for the final demonstration.

Tuesday, Nov 10 · Day 4/4

  1. Set up all objects as specified in the original project manual.
  2. Run the complete two-workcell sorting demonstration.
  3. Record correct deliveries, missed or misplaced objects, interruptions, total run time, and any necessary resets.
  4. Explain your division of tasks, code design choices, reliability, and the most valuable improvement.

Submit: system plan, both programs, performance data, debugging log, and reflection.

Friday programming checkpoint

  • Two saved, named, commented VEXcode EXP program files, one per workcell.
  • Routing diagram or numbered process plan showing all four destination rules and required object quantities.
  • Clear partner-team coordination responsibilities and transfer/handoff logic.
  • Logical dry-run records and at least three identified failure cases with planned responses.
  • Monday testing checklist for motor directions, sensors, diverters, arm positions, and handoff timing.

Important: A dry-run on November 5–6 is not evidence that a machine operated successfully. Your instructor will supervise actual testing on November 9. Optimize the system for speed, reliability, efficiency, and minimal sensor use as identified in the PLTW manual.

Student Workflow

What You Will Do

  1. Review the production requirements and destination rules.
  2. Plan how each workcell will sense, move, sort, and transfer objects.
  3. Program and test each workcell independently before connecting the process.
  4. Run the complete sorting sequence repeatedly and record failures or delays.
  5. Revise the system until it meets the required routing and reliability targets.
Programming Focus

How coding supports the lesson

Combine sensor-based conditionals, loops, conveyor control, robotic-arm movement, and pneumatic actions. Timing may still be used for cross-workcell coordination here; Project 2.2.4 will replace that weakness with handshaking.
