Objective

Connect a measured vision signal to an actuator decision, with persistence to reduce rapid switching.

Materials

A webcam, green object and Simulator first. Board extension requires teacher approval and the standard firmware.

Plan your time

40–50 minutes. Follow your teacher’s schedule.

Start in Programming Studio

Open the lesson link above, then select Open requested lesson. Studio saves your current project before opening a separate named lesson project. It does not replace your saved work or start the camera or hardware automatically.

Wait for Python ready. The starter sets Live vision mode. Use the guided setup, evidence checklist and observations field in Studio as you work.

Simulator first: real Arduino testing is optional until your teacher has validated the wiring, power, safe travel and Stop behavior. A webcam is needed for the vision lessons. No AI coding assistant is used.

Build & test

  1. Open the lesson as a new project, start the camera and choose Simulator. Arm hardware, then select Run live.
  2. Fill more than 8% of the image with a green object for three frames. The gate should move to 150° and the LED should turn on.
  3. Remove the object for three frames. The gate should return to 30° and the LED should turn off. Watch the ratio and pending-frame count on the preview.
  4. Test small objects, brief appearances and changes in lighting. Stop and restart to adjust MIN_RATIO or STABLE_FRAMES, then compare results.
  5. After a successful simulation, ask your teacher to check the wiring and gate travel. Stop before choosing USB Arduino. Connect, arm and run the same code with an unloaded servo before attaching a lightweight gate.
  6. Test Stop and tab switching. The program must stop and disarm. Servo detachment does not mechanically brake a gate; keep loads safe.
Read the Python starter
import cv2

MIN_RATIO = 0.08
STABLE_FRAMES = 3
candidate = None
streak = 0
last_sent = None

async def process_frame(frame):
    global candidate, streak, last_sent
    rgb = cv2.cvtColor(frame, cv2.COLOR_RGBA2RGB)
    hsv = cv2.cvtColor(rgb, cv2.COLOR_RGB2HSV)
    mask = cv2.inRange(hsv, (35, 70, 60), (85, 255, 255))
    ratio = cv2.countNonZero(mask) / mask.size
    detected = ratio >= MIN_RATIO
    if detected == candidate:
        streak += 1
    else:
        candidate, streak = detected, 1
    if streak >= STABLE_FRAMES and detected != last_sent:
        await arduino.servo(150 if detected else 30)
        await arduino.led(detected)
        last_sent = detected
    label = f"Green {ratio:.0%} | stable {min(streak, STABLE_FRAMES)}/{STABLE_FRAMES}"
    cv2.putText(frame, label, (10, 25), cv2.FONT_HERSHEY_SIMPLEX,
                0.6, (255, 220, 40, 255), 2)
    return frame

Evidence to collect

  • I tested both gate positions in simulation.
  • I tested a brief appearance and explained the three-frame rule.
  • I verified Stop and recorded simulation versus physical testing separately.

Observations & reflection

Record at least four trials and the gate result. How did STABLE_FRAMES reduce switching? State whether you tested simulation only or a teacher-approved physical board.

Extend the challenge

Use separate enter/exit ratio thresholds to reduce switching near the boundary. Explain why persistence is measured in frames, not fixed seconds.

What to submit
