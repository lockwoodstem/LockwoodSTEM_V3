Objective

Connect a measured vision signal to an actuator decision, with persistence to reduce rapid switching.

Materials

A webcam, green object and Simulator first. Board extension requires teacher approval and the standard firmware.

Plan your time

40–50 minutes. Follow your teacher’s schedule.

Learn: connect vision to a controlled gate

The previous lessons introduced decision rules and image measurements. This project joins them: camera pixels → green mask → measured fraction → stable decision → LED and servo gate. Begin with the simulator so you can test the logic without a physical mechanism.

Measure a fraction of the whole image

ratio = cv2.countNonZero(mask) / mask.size divides the number of matching pixels by the total number of pixels. MIN_RATIO = 0.08 means a detection requires at least 8% of the frame to match green. This counts all green pixels, including separate patches and background; it does not count objects or use the contour-area filter from Lesson 2.1.9.

For a 640 × 480 frame, there are 307,200 pixels. A green count of 24,576 gives 24,576 / 307,200 = 0.08 and passes the >= comparison. A smaller count does not. Use this calculation as a prediction; the displayed percentage is rounded, so a display of 8% alone does not establish which side of the boundary the exact ratio occupies.

Require evidence across several frames

A single noisy frame should not move a gate. candidate stores the newest proposed decision; streak counts consecutive frames agreeing with it. A changed decision resets the streak to 1. At STABLE_FRAMES = 3, the program sends an output after three agreeing frames. last_sent avoids sending the same output on every subsequent frame.

At startup, no command has been confirmed yet: the first three agreeing frames establish the initial gate position. Three frames is not a fixed number of seconds; processing speed affects the delay. Persistence reduces brief switching but does not prove that an object is correctly classified or safely routed.

Predict before opening Studio

Start from a confirmed non-green scene. Predict the gate response to two green frames followed by one non-green frame, then to three green frames. Explain how increasing STABLE_FRAMES to 5 changes both resistance to brief appearances and response delay.

Guided investigation

Start the camera, select Simulator, arm hardware, and Run live. First hold an empty non-green view long enough to confirm 30°. Then show a large green object until 150° is confirmed, and remove it until the gate returns. Watch the preview ratio and frame count along with the servo and LED.

Test a small green object, a brief appearance, and a lighting change. Change only MIN_RATIO or STABLE_FRAMES between runs. Record at least four trials: scene, settings, expected response, observed ratio/streak and gate result, and explanation. Stop and restart Python before edits; restart the camera and arm again before Run live.

If the result is unexpected

  • No output at startup: wait for three agreeing frames and check that hardware is armed.
  • A short appearance does nothing: the persistence rule may be working as intended.
  • The gate remains at 150° after removal: check for green background pixels and allow three confirmed non-green frames.
  • Output switches near the boundary: simplify lighting and compare a larger STABLE_FRAMES setting; explain the added delay.

Validate the system, then explain its limits

Test Stop and switching to another tab. The program must stop and disarm; the camera should switch off. Keep simulator evidence separate from physical evidence. Simulation validates program decisions but cannot validate wiring, power, gate travel, pinch points, or whether a real object reaches the intended bin. Physical extension requires your teacher’s check with an unloaded servo first.

Explain the difference between detecting green and successfully sorting an object. What additional mechanical and timing evidence would be needed for the final sorting-machine project?

Upload and connect

  1. Download the LockwoodStudio.ino file and open it in Arduino IDE. If prompted, allow the IDE to place it in a folder named LockwoodStudio.
  2. Select the correct Arduino Uno R3 or classic Nano board and USB port, then click Upload. The standard Servo library is included with Arduino IDE.
  3. Close Serial Monitor and any application that is using the serial port.
  4. Open Studio, choose USB Arduino, select Connect board, and wait for Firmware v1 ready.
  5. Verify wiring and safe servo travel with your teacher, then select Arm hardware and run the lesson code. Select Stop when finished.

Uno R3 / classic Nano: built-in LED on D13, servo signal on D9, potentiometer center pin on A0 with outer pins connected to 5V and GND. Use a suitable regulated external servo supply with common ground; disconnect power before wiring.

Safety: Test with an unloaded servo first. The firmware turns off the LED and detaches servo control after a communication timeout, but detaching does not remove servo power or mechanically stop a moving load.

Build & test

  1. Open the lesson as a new project, start the camera and choose Simulator. Arm hardware, then select Run live.
  2. Fill more than 8% of the image with a green object for three frames. The gate should move to 150° and the LED should turn on.
  3. Remove the object for three frames. The gate should return to 30° and the LED should turn off. Watch the ratio and pending-frame count on the preview.
  4. Test small objects, brief appearances and changes in lighting. Stop and restart to adjust MIN_RATIO or STABLE_FRAMES, then compare results.
  5. After a successful simulation, ask your teacher to check the wiring and gate travel. Stop before choosing USB Arduino. Connect, arm and run the same code with an unloaded servo before attaching a lightweight gate.
  6. Test Stop and tab switching. The program must stop and disarm. Servo detachment does not mechanically brake a gate; keep loads safe.
Read the Python starter
import cv2

MIN_RATIO = 0.08
STABLE_FRAMES = 3
candidate = None
streak = 0
last_sent = None

async def process_frame(frame):
    global candidate, streak, last_sent
    rgb = cv2.cvtColor(frame, cv2.COLOR_RGBA2RGB)
    hsv = cv2.cvtColor(rgb, cv2.COLOR_RGB2HSV)
    mask = cv2.inRange(hsv, (35, 70, 60), (85, 255, 255))
    ratio = cv2.countNonZero(mask) / mask.size
    detected = ratio >= MIN_RATIO
    if detected == candidate:
        streak += 1
    else:
        candidate, streak = detected, 1
    if streak >= STABLE_FRAMES and detected != last_sent:
        await arduino.servo(150 if detected else 30)
        await arduino.led(detected)
        last_sent = detected
    label = f"Green {ratio:.0%} | stable {min(streak, STABLE_FRAMES)}/{STABLE_FRAMES}"
    cv2.putText(frame, label, (10, 25), cv2.FONT_HERSHEY_SIMPLEX,
                0.6, (255, 220, 40, 255), 2)
    return frame
